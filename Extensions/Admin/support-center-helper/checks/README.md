# Регрессионные проверки Support Center Helper

Все данные искусственные. Тесты не используют профиль пользователя, авторизацию или рабочий API Яндекс 360.

## Логика хранилища и перехватчика

Нужен Node.js 20+; дополнительных библиотек нет:

```sh
node --test checks/storage.test.cjs checks/interceptor.test.cjs checks/content.test.cjs checks/navigation.test.cjs
```

Проверяются восстановление состояния в новом экземпляре worker, несколько вкладок/организаций, пагинация, обновление полей и порядка, пустые ответы, фильтры, запоздавшие ответы, ошибки записи и CSV. Для перехватчика проверяются ранние события, fetch с Request, XHR, пакетные модели и ответы с ошибками. Добавлены случаи `status: "OK"`, пустого `errors: []`, отсутствующего ID модели в ответе и несовпадения ID текущего тикета с адресом. Текущий скрытый тикет сохраняется как точка отсчёта навигации.

## Браузерная проверка

Нужны Playwright и его Chromium:

```sh
node checks/browser-smoke.cjs
```

Стенд запускает установленное расширение в настоящем Chromium с временным профилем. Все HTTP-запросы к `admin.yandex.ru` и `admin.360.yandex.ru` получают локальные тестовые ответы; остальные внешние запросы страниц блокируются.

Проверяются:

- ранний ответ списка до окончания загрузки DOM и пагинация через XHR;
- обновление списка и отдельного тикета;
- переходы «Следующий» / «Предыдущий» с новой загрузкой документа;
- SPA-переходы в тикет и обратно;
- поздняя отрисовка шапки через 6,1 секунды и её замена приложением;
- изменение настроек, скрытие строк, отключение/включение навигации;
- активные кнопки и перезагрузка открытого тикета, подпадающего под оба включённых фильтра;
- восстановление ID из запроса карточки, когда адрес использует другой идентификатор;
- приоритет ID из адреса над фоновой загрузкой данных другого тикета;
- настоящий клик по ссылке тикета, отличающийся контекст ответа карточки и пустой вспомогательный запрос списка;
- запоздалый пустой ответ после клика со SPA-переходом;
- различие счётчика строк таблицы и собранного списка, чтение безопасной диагностики из popup;
- неполные записи без поля темы, отсутствие ложной фильтрации всех записей;
- ноль доступных с фильтрами записей и немедленное восстановление экспорта при отключении фильтра;
- четыре сохранённых тикета: переключение «без темы» кликом в popup, позиция скрытого текущего тикета и переходы в обе стороны;
- все четыре тикета без темы: текущий тикет найден, а отключённые кнопки объясняют отсутствие подходящих соседей;
- автоматическая дозагрузка после скрытия строк: первые 15 и следующие 4 дают 19 собранных тикетов, сохраняются текущий тикет, переходы и перезагрузка;
- остановка **реального** service worker через CDP и восстановление данных после запуска;
- разные вкладки, адресация popup, загрузка CSV и очистка только активной вкладки;
- оба адреса панели администратора, пустая выборка и пустое продолжение.

Это проверка браузерных API и интеграции компонентов расширения. Она не подтверждает неизменность внутреннего API и DOM рабочего Центра поддержки. Запуск в авторизованной рабочей панели и непосредственно в Яндекс Браузере проводится отдельно.

```sh
python3 checks/build_zip.py
```
