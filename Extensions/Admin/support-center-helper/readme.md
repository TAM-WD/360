# Support Center Helper 2.5.4

Расширение с полезными опциями для Центра поддержки в панели администратора Яндекс 360.

[Скачать ZIP версии 2.5.4](support-center-helper.zip)

## Возможности

- Скрытие тикетов «Без темы» и архивированных тикетов.
- Счётчик загруженных строк и собранных тикетов.
- Выгрузка собранных тикетов в CSV.
- Кнопки «Предыдущий» и «Следующий» внутри тикета.

Расширение собирает только те тикеты, которые загрузила страница Центра поддержки. Для сбора следующих порций прокрутите список или используйте штатную пагинацию сайта. Самостоятельной выгрузки всей организации нет.

## Установка и обновление

1. Распакуйте `support-center-helper.zip` в отдельную папку или используйте эту папку с исходниками.
2. Откройте `chrome://extensions/` в Chrome или `browser://extensions/` в Яндекс Браузере.
3. Включите режим разработчика и нажмите «Загрузить распакованное расширение».
4. Выберите папку, в которой находится `manifest.json`.
5. Для обновления ранее установленной распакованной версии замените её файлы и нажмите «Обновить» / кнопку перезагрузки расширения на странице расширений.
6. Обновите открытые вкладки Центра поддержки. В popup должна отображаться версия **2.5.4**. Откройте список тикетов и включите «Навигация внутри тикета».

Не оставляйте одновременно включёнными старую и новую копии расширения: обе будут вмешиваться в одну страницу.

**Файл `support-center-helper.crx` в репозитории — старая версия 2.4, без этих исправлений.** Для версии 2.5.4 используйте папку или ZIP. Обновление подписанного CRX с прежним ID требует исходного ключа подписи; новый ключ автоматически не создаётся.

## Оформление кнопок в 2.5.4

- Возвращены стрелки: «‹ Предыдущий» и «Следующий ›».
- При наведении появляется скруглённая обводка и фоновая подсветка по образцу штатной кнопки «Назад». Размер кнопок при наведении не меняется; неактивные кнопки не подсвечиваются.

## Исправление дозагрузки в 2.5.3

В диагностике наблюдалась замена 15 собранных записей последними 4. Если эти 4 записи были без темы, фильтр исключал их все, а ранее открытый тикет исчезал из выборки. Такой сброс воспроизведён в тестах: неизвестный параметр продолжения ошибочно считался изменением фильтра.

- Критерии выборки и параметры страниц учитываются отдельно. Дополнительная порция дополняет список, включая неизвестные параметры продолжения.
- Пустые необязательные фильтры (`null`, пустая строка, массив или объект) эквивалентны отсутствующим и не сбрасывают выборку между страницами.
- Порядок страниц сохраняется при дозагрузке и запоздавших ответах; обновление первой страницы не удаляет ранее загруженное продолжение.
- В диагностике операций списка добавлены число записей в ответе, число сохранённых страниц и признак смены выборки. Сценарий теста теперь показывает `15 → 19` при получении ещё 4 записей.

## Изменения в 2.5.2

- Если ID из адреса найден в собранном списке, он имеет приоритет над ID из запросов других карточек на этой странице.
- Ответ карточки обновляет только уже известную запись в том же контексте. Он не очищает список и не меняет его организацию, учётную запись или фильтры.
- Ответы списка принимаются, только если запрос начался на странице списка и пришёл, пока она оставалась открыта. Запросы из карточки и запоздалые ответы после ухода в карточку не заменяют выборку.
- Некорректные элементы ответа не считаются пустой выборкой и не стирают сохранённые данные.
- В карточке верхний счётчик показывает «Открыта карточка тикета», а число собранных записей остаётся под CSV. Верхний счётчик относится к строкам таблицы, а не к сохранённому списку.
- Отдельный счётчик «Доступно с фильтрами» показывает число возможных целей перехода и записей CSV. Когда все записи отфильтрованы, кнопка экспорта объясняет причину. После выключения последнего фильтра счётчик и экспорт обновляются сразу.
- Отсутствующее в ответе API поле темы считается неизвестным. Фильтр «без темы» исключает только явно пустую тему или «Без темы».
- Раздел popup «Диагностика навигации» показывает доступность списка, наличие текущего ID и последние 12 причин обработки. В диагностике нет ID учётной записи, ID тикетов, тем, авторов или текстов обращений. Если проблема сохраняется, скопируйте текст этого раздела после открытия тикета.

Если «Собрано» больше нуля, но «Доступно с фильтрами» равно нулю, записи сохранены, а переходы и CSV ограничены включёнными фильтрами. Временно выключите оба фильтра для проверки. Если кнопки по-прежнему сообщают, что текущего тикета нет в списке, сохраните диагностику; сам факт наличия записей не подтверждает, что среди них есть открытый тикет.

## Исправление неактивных кнопок в 2.5.1

- Если открытый тикет подпадает под «Скрывать архивированные» или «Скрывать без темы», он сохраняет свою позицию для перехода к видимым соседям. Остальные скрытые тикеты пропускаются; CSV по-прежнему учитывает фильтры.
- Текущий ID определяется также из запроса карточки, если адрес использует другой идентификатор. Запоздалый ответ предыдущей страницы не меняет текущую позицию.
- Успешные ответы со статусом `OK`, пустым `errors: []` и без повторения ID модели больше не отбрасываются. Ошибочные и неоднозначные ответы не заменяют список.
- Подсказка неактивной кнопки различает пустой список, отсутствие текущего тикета, границу списка и отсутствие соседей после фильтрации.

## Как сохраняется список

- Тикеты, фильтры и порядок страниц сохраняются в `chrome.storage.session`, отдельно для каждой вкладки. Внутри вкладки учитываются организация и `uid`.
- Переходы между тикетами, возврат в список, обновление страницы и остановка фонового service worker не очищают собранные данные.
- Повторная загрузка первой страницы с теми же фильтрами обновляет эту порцию, сохраняя ранее загруженные тикеты за её пределами (в том числе при меньшем `limit` после обновления страницы). Поля повторно полученных тикетов обновляются, порядок порции берётся из ответа сервера.
- Смена фильтров или сортировки на странице списка создаёт новую выборку. Пустая первая страница очищает прежнюю выборку; пустая следующая страница означает конец пагинации. Запросы, сделанные в карточке, не создают новую выборку.
- Фильтры «Без темы» и «Архивированные» применяются к целям переходов и CSV при чтении. Их переключение не удаляет тикеты из сохранённого списка и не лишает открытый тикет позиции для перехода к видимому соседу.
- Навигацию можно включить уже после загрузки списка. Кнопки восстанавливаются при новой загрузке страницы, позднем появлении шапки и её перерисовке.
- «Очистить список этой вкладки» удаляет только список активной вкладки. Закрытие вкладки также удаляет её данные.
- Перезапуск браузера, отключение, обновление или перезагрузка **самого расширения** очищают `storage.session`. После этого список нужно собрать заново. Настройки сохраняются в `chrome.storage.local`.

Сохранённые последующие страницы — снимки уже полученных ответов: расширение не обновляет их на сервере автоматически. Обновление счётчиков popup раз в две секунды не является загрузкой тикетов.

## Устройство

- `interceptor.js` — перехватывает `fetch`/XHR в MAIN на `document_start`, включая `Request`, пакетные модели и пустые ответы. До готовности content script события буферизуются.
- `content.js` — принимает ответы в ISOLATED, передаёт их фоновому обработчику, применяет настройки к строкам таблицы.
- `navigation.js` — создаёт кнопки и читает актуальный список через сообщения расширения; работает в ISOLATED, без передачи настроек одноразовыми событиями страницы.
- `background.js` — последовательно обрабатывает операции каждой вкладки, сохраняет состояние до подтверждения записи, формирует навигацию и CSV.
- `popup.js` — настройки, счётчики, экспорт и очистка для активной вкладки.

Критерии выборки перечислены в `FILTER_KEYS` файла `background.js`: организация и `uid`, тема, авторы, продукты, статусы, диапазоны дат, поиск, сортировка и вложенные `filter`/`filters`. Остальные параметры запроса образуют идентификатор порции; изменение `limit`, `page_size`, `per_page` само по себе не создаёт новую выборку или порцию. Поддерживаются курсоры, `offset`, `page`, `page_number` и вложенный `pagination`. Если сайт добавит новый предметный фильтр вне `filter`/`filters`, его ключ нужно добавить в `FILTER_KEYS`.

## Проверка

Регрессионные проверки и браузерный стенд находятся в `checks/`. Инструкции и границы проверки — в `checks/README.md` в исходном репозитории. В установочный ZIP проверки не включены.

Требуется Chromium с поддержкой Manifest V3, MAIN content scripts и `storage.session` (Chrome 111+). Целевой пользовательский браузер — Яндекс Браузер 25.10+.

Официальная документация Chrome: [жизненный цикл service worker](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage), [content scripts](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts).
