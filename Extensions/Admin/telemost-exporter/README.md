# Экспорт аналитики встреч Телемоста в XLSX

Расширение версии 0.2.0 для браузеров с поддержкой Chrome Manifest V3. Работает через открытую аналитику организации Яндекс 360. Сборка и установка пакетов не нужны.

| Данные | Что выгружается |
|---|---|
| Встреча | ID конференции и её сессии, название при наличии, имя организатора, начало, конец, длительность, состояние, MOS |
| Число участников | Общее число по API, пик одновременно, число выгруженных строк участников |
| Участник | ID участника, отображаемое имя, первое появление, последний выход, MOS отправки/приёма |
| Устройства | Платформа, версия приложения, названия камеры, аудиоустройства и устройств демонстрации при наличии |
| Дополнительные поля | Разрывы `reconnect_count`, время подключения `connection_time_ms`, CPU, даты зала ожидания — только когда сервер их возвращает |
| Качество | Средние и максимальные bitrate, потери пакетов, RTT, jitter для аудио, видео и демонстрации в обоих направлениях |
| Подробные замеры | По галочке: временные ряды качества, 6 комбинаций отправки/приёма и аудио/видео/демонстрации видео |
| IP | Отдельная галочка, по умолчанию выключена |
| Дополнительные вложенные данные | Непустые поля участника и качества разворачиваются в дополнительные столбцы с русскими названиями |
| Полнота | Статус сбора и отдельный лист с ошибками и предупреждениями |

## Установка и первый запуск

1. Скачайте [репозиторий TAM-WD/360](https://github.com/TAM-WD/360) через **Code → Download ZIP** и распакуйте его либо используйте локальную копию репозитория. Папка расширения: `Extensions/Admin/telemost-exporter`.
2. Откройте страницу управления расширениями браузера. В Chrome это `chrome://extensions`, в Edge — `edge://extensions`.
3. Включите режим разработчика, выберите «Загрузить распакованное» и укажите папку `telemost-exporter`, в которой находится `manifest.json`.
4. Войдите администратором в [кабинет организации](https://admin.yandex.ru/telemost-monitoring) и откройте аналитику встреч Телемоста. **После установки обновите страницу кабинета**: расширение должно увидеть обычный запрос списка встреч.
5. Нажмите значок расширения. ID организации подставится из запроса кабинета. Если кабинет ещё не найден, нажмите «Обновить» в попапе после обновления страницы кабинета.
6. Задайте обе даты и часовой пояс, при необходимости включите IP и подробные замеры, нажмите «Скачать XLSX».
7. Откроется вкладка сбора. **Оставьте открытыми вкладку сбора и исходную вкладку аналитики.** Попап можно закрыть. Не меняйте организацию в исходной вкладке до окончания.
8. После сбора начнётся скачивание. При необходимости нажмите кнопку повторного скачивания. При остановке можно скачать уже собранную часть.

Ручной ID организации позволяет выбрать только организацию, для которой расширение уже видело запрос в открытом кабинете. Переключение организации выполняется в самом кабинете.

Целевая платформа — Chromium с Manifest V3, `chrome.scripting` и `chrome.webRequest`. Firefox и Safari этой сборкой не поддерживаются.

## Как устроена книга

- **Описание** — период, часовой пояс, статус, счётчики и определения показателей.
- **Встречи** — одна строка на пару `conference_id + session_id`. Одна постоянная ссылка может иметь несколько сессий.
- **Участники** — одна строка на `participant_id` внутри сессии; дополнительные непустые данные карточки представлены отдельными столбцами с русскими названиями.
- **Качество** — одна строка на участника и непустой тип медиапотока. Заголовки переведены на русский язык.
- **Замеры** — появляется при включённой опции. Одна строка на метрику и момент времени, с единицей измерения.
- **Ошибки** — этап, ID сущности, HTTP-статус, описание и время ошибки.

Листы содержат фильтры и закреплённую шапку. Числа и даты — числовые значения Excel; длинные ID — текст. Строки, начинающиеся с `=`, `+`, `-`, `@`, сохраняются текстом, формулы не выполняются. Большие наборы строк разбиваются на несколько листов.

Даты Excel отображаются в выбранном часовом поясе, указанном в заголовках. Начало и конец периода включают выбранные календарные дни целиком.

Период определяется **по началу встречи**. В API передаются `date_from` и `date_to`, затем проверяется `start_date`. Встречи без даты начала сохраняются с предупреждением. Встречи, начавшиеся до периода и продолжавшиеся внутри него, не входят в заданное определение.

## Что означают показатели

- `total_participants_count` — счётчик количества участников. 
- `max_active_participants_count` — пик одновременного присутствия.
- `participant_id` ID подключение участника. Один человек с несколькими устройствами может иметь несколько строк. По одинаковым именам люди не объединяются.
- `reconnect_count` — переподключения. 
- Временная граница от первого появления до последнего выхода может включать отсутствие. 
- `connection_time_ms` сохраняется в миллисекундах, когда присутствует.
- Метрики качества: bitrate — бит/с, packet loss — доля, RTT и jitter — мс.
