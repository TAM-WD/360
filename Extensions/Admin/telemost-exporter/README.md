# Экспорт аналитики встреч Телемоста в XLSX

Расширение версии 0.2.0 для браузеров с поддержкой Chrome Manifest V3. Работает через открытую аналитику организации Яндекс 360. Сборка и установка пакетов не нужны.

## Важный результат исследования HAR

**Количество участников и устройства доступны. Отдельных логинов и точного числа входов в исследованных ответах нет.**

Расширение не превращает отображаемое имя в логин и не выдаёт число разрывов за число входов. Столбцы логина и числа входов в книгу не добавляются. Для выгрузки этих сведений потребуется дополнительный подтверждённый источник с привязкой к учётной записи и журналом подключений.

| Данные | Что выгружается |
|---|---|
| Встреча | ID конференции и её сессии, название при наличии, имя организатора, начало, конец, длительность, состояние, MOS |
| Число участников | Общее число по API, пик одновременно, число выгруженных строк участников |
| Участник | ID участника, отображаемое имя, первое появление, последний выход, MOS отправки/приёма |
| Устройства | Платформа, версия приложения, названия камеры, аудиоустройства и устройств демонстрации при наличии |
| Дополнительные поля | Разрывы `reconnect_count`, время подключения `connection_time_ms`, CPU, даты зала ожидания — только когда сервер их возвращает |
| Качество | Средние и максимальные bitrate, потери пакетов, RTT, jitter для аудио, видео и демонстрации в обоих направлениях |
| Подробные замеры | По галочке: временные ряды качества, 6 комбинаций отправки/приёма и аудио/видео/демонстрации видео |
| IP | Отдельная галочка, по умолчанию выключена |
| Дополнительные вложенные данные | Непустые поля участника и качества разворачиваются в дополнительные столбцы с русскими названиями |
| Полнота | Статус сбора и отдельный лист с ошибками и предупреждениями |

## Установка и первый запуск

1. Скачайте [репозиторий TAM-WD/360](https://github.com/TAM-WD/360) через **Code → Download ZIP** и распакуйте его либо используйте локальную копию репозитория. Папка расширения: `Extensions/Admin/telemost-exporter`.
2. Откройте страницу управления расширениями браузера. В Chrome это `chrome://extensions`, в Edge — `edge://extensions`.
3. Включите режим разработчика, выберите «Загрузить распакованное» и укажите папку `telemost-exporter`, в которой находится `manifest.json`.
4. Войдите администратором в [кабинет организации](https://admin.yandex.ru/telemost-monitoring) и откройте аналитику встреч Телемоста. **После установки обновите страницу кабинета**: расширение должно увидеть обычный запрос списка встреч.
5. Нажмите значок расширения. ID организации подставится из запроса кабинета. Если кабинет ещё не найден, нажмите «Обновить» в попапе после обновления страницы кабинета.
6. Задайте обе даты и часовой пояс, при необходимости включите IP и подробные замеры, нажмите «Скачать XLSX».
7. Откроется вкладка сбора. **Оставьте открытыми вкладку сбора и исходную вкладку аналитики.** Попап можно закрыть. Не меняйте организацию в исходной вкладке до окончания.
8. После сбора начнётся скачивание. При необходимости нажмите кнопку повторного скачивания. При остановке можно скачать уже собранную часть.

Ручной ID организации позволяет выбрать только организацию, для которой расширение уже видело запрос в открытом кабинете. Переключение организации выполняется в самом кабинете.

Целевая платформа — Chromium с Manifest V3, `chrome.scripting` и `chrome.webRequest`. Совместимость с конкретной версией Яндекс Браузера ещё требует проверки. Firefox и Safari этой сборкой не поддерживаются.

## Как устроена книга

- **Описание** — период, часовой пояс, статус, счётчики и определения показателей.
- **Встречи** — одна строка на пару `conference_id + session_id`. Одна постоянная ссылка может иметь несколько сессий.
- **Участники** — одна строка на `participant_id` внутри сессии; дополнительные непустые данные карточки представлены отдельными столбцами с русскими названиями.
- **Качество** — одна строка на участника и непустой тип медиапотока. Заголовки переведены на русский язык.
- **Замеры** — появляется при включённой опции. Одна строка на метрику и момент времени, с единицей измерения.
- **Ошибки** — этап, ID сущности, HTTP-статус, описание и время ошибки.

Листа с исходными ответами API в книге нет. Пустые объекты и массивы не создают дополнительные столбцы; непустые вложенные данные участника и качества сохраняются. Неизвестные поля получают подписи «Дополнительное поле N» без предположений об их смысле. Числовой ноль считается значением и не удаляется как пустота. Длинные вложенные значения разбиваются между столбцами с номером части; для восстановления объедините части по порядку.

Листы содержат фильтры и закреплённую шапку. Числа и даты — числовые значения Excel; длинные ID — текст. Строки, начинающиеся с `=`, `+`, `-`, `@`, сохраняются текстом, формулы не выполняются. Большие наборы строк разбиваются на несколько листов.

Даты Excel отображаются в выбранном часовом поясе, указанном в заголовках. Начало и конец периода включают выбранные календарные дни целиком.

Период определяется **по началу встречи**. В API передаются `date_from` и `date_to`, затем проверяется `start_date`. Встречи без даты начала сохраняются с предупреждением. Встречи, начавшиеся до периода и продолжавшиеся внутри него, не входят в заданное определение.

## Что означают показатели

- `total_participants_count` — счётчик сервера. Его нельзя без проверки называть количеством уникальных сотрудников или людей.
- `max_active_participants_count` — пик одновременного присутствия.
- `participant_id` не является подтверждённым ID учётной записи. Один человек с несколькими устройствами может иметь несколько строк. По одинаковым именам люди не объединяются.
- `reconnect_count` кабинет подписывает как **«Разрывы»**. Формула `разрывы + 1 = входы` не подтверждена и не применяется.
- Временная граница от первого появления до последнего выхода может включать отсутствие. Разность этих времён не выдаётся за точное время присутствия.
- `connection_time_ms` сохраняется в миллисекундах, когда присутствует.
- По преобразованиям кода кабинета: bitrate — бит/с, packet loss — доля, RTT и jitter — мс. MOS сохраняется как оценка API. Метрики не пересчитываются.
- Отсутствующее значение остаётся пустым. Ноль означает полученный от сервера ноль.

## Сбор и обработка ошибок

Списки встреч и участников обходятся отдельно по `iteration_key`, по 15 записей на страницу. Курсор передаётся без изменения. Повторяющийся курсор, неожиданный формат карточки и расхождение числа участников фиксируются как предупреждение о неполноте.

Запросы выполняются последовательно с небольшой паузой. Для временных сетевых ошибок, HTTP 429 и 5xx есть до трёх повторов. При 401/403 сбор прекращается с предложением повторно войти в кабинет. Ответы ошибок сервера и секретные заголовки в отчёт не копируются.

- `complete` — обход завершился без обнаруженных ошибок.
- `partial` — есть пропуски или предупреждения; смотрите лист «Ошибки».
- `cancelled` — пользователь остановил сбор; файл содержит только уже собранные данные.

Отмена ожидает завершения текущего запроса, максимум 25 секунд. Работа не переживает закрытие вкладки сбора или браузера; автоматического восстановления нет. Данные живого API могут измениться во время обхода. Срок хранения, права администратора и доступность сервиса определяют, какие встречи вообще можно получить.

Подробные замеры добавляют до шести запросов на участника и увеличивают время и размер файла. XLSX собирается в памяти без сжатия ZIP; очень большие периоды лучше выгружать частями. Выгрузка требует доступной памяти браузера; ZIP64 для файлов от 4 ГБ не поддерживается.

## Доступы и хранение

Разрешения расширения ограничены `admin.yandex.ru`, `admin.telemost.yandex.ru`, `cloud-api.yandex.ru`, наблюдением запросов, выполнением своего кода в нужном фрейме и временным хранилищем заданий.

Расширение выполняет только GET к перечисленным методам аналитики, используя авторизованную вкладку. Cookie и токены не читает. Наблюдатель запросов сохраняет только ID организации, вкладки, фрейма и время наблюдения. Временное хранилище содержит параметры задания; участники и ответы API обрабатываются в памяти вкладки сбора до её закрытия. В скачанный файл попадают подготовленные таблицы.

Файл строится локально. Аналитика расширения, внешние CDN и отправка отчёта на сторонний сервер отсутствуют. При выключенной опции IP очищается и из обычных столбцов, и из дополнительных данных. Поля с названиями токенов/паролей/авторизации и параметры URL исключаются из выгрузки.

## Что проверено и что осталось проверить

API восстановлен по предоставленному HAR и сохранённому в нём коду кабинета. Проверены синтетические сценарии пагинации обоих списков, границ дат, повторов, отказа доступа, остановки, частичной выгрузки, очистки IP и отсутствующих полей. Проверены попап и вкладка сбора в моделируемом DOM.

Также выполнен сквозной офлайн-прогон обезличенных ответов из HAR через сборщик и генератор книги: 3 встречи, 4 строки участников и явная отметка о неполноте отсутствующих в записи запросов.

XLSX проверен независимым чтением через openpyxl: ZIP/XML, типы, длинные ID, даты, текст вместо формул, фильтры, закрепление шапки и ограничения Excel.

Пользователь уже получил XLSX-выгрузку в реальном кабинете. Автоматический сквозной тест браузерного сценария не завершён. Отдельно требуется проверить даты у границ выбранного периода, последние страницы больших списков встреч и участников и полноту выгрузки на таких объёмах. Результат отдельного запуска не подтверждает эти случаи. HAR и пользовательские выгрузки в состав расширения не входят.

## Возможные следующие улучшения

1. Подключить подтверждённый журнал входов и источник учётных записей для добавления логинов и точного числа входов.
2. Добавить сводки по дням и платформам. Для статистики по сотрудникам сначала нужна достоверная привязка участника к учётной записи.
3. Добавить возобновление больших выгрузок после закрытия браузера; для этого отдельно решить хранение локальных данных участников.

## Технические источники

Реализация использует [Chrome Scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting), [Web Request API](https://developer.chrome.com/docs/extensions/reference/api/webRequest) и правила [запросов из расширений и content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests). Сам API Телемоста исследован по HAR; публичного контракта для этих методов в задаче не было.
