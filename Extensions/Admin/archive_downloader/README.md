# Помощник аудита и архива Яндекс 360

Браузерное расширение **Yandex Admin Audit & Stash Helper**, версия **1.3**. Находит почтовые события сотрудника в журнале аудита, сопоставляет их с архивом по MID и пересылает найденные письма в указанный ящик. События, список архивных писем и отчёт о пересылке можно выгрузить в XLSX.

Восстановление здесь выполняется пересылкой в выбранный ящик. XLSX содержит события и метаданные; тела писем и вложения в эти файлы не скачиваются.

## Установка

1. Склонируйте или скачайте репозиторий [TAM-WD/360](https://github.com/TAM-WD/360). Если скачали репозиторий архивом, распакуйте его.
2. Откройте страницу управления расширениями Chromium-браузера. В Chrome это `chrome://extensions`.
3. Включите режим разработчика и нажмите **«Загрузить распакованное»**.
4. Выберите папку **`Extensions/Admin/archive_downloader`** из репозитория. В ней должны лежать `manifest.json`, `popup.html`, `popup.js`, `background.js` и `xlsx.full.min.js`.

Сборка и установка зависимостей не нужны: библиотека XLSX включена в папку расширения. Отдельный архив расширения для установки не требуется.

## Перед началом

1. Войдите в нужную организацию на `admin.yandex.ru` под администратором с доступом к журналу аудита и архиву писем.
2. **Вручную откройте [Архив писем](https://admin.yandex.ru/stash) и пройдите проверку номера телефона, если кабинет её запрашивает. Сделайте это до работы с расширением.**
3. Подготовьте **Org ID** организации и **UID сотрудника**, чьи события и письма нужны. UID — идентификатор сотрудника, а не его почтовый адрес.

Во время операций оставляйте окно расширения открытым и выполняйте шаги последовательно. Сохранение результатов происходит после завершения соответствующего действия; закрытие окна во время запроса не является способом приостановить и затем продолжить работу.

## 1. Инициализировать сессию

Заполните **Org ID** и **UID сотрудника**, нажмите **«Инициализировать сессию»** и дождитесь зелёного статуса.

При инициализации расширение обращается к журналу аудита и получает служебный токен для запросов. Зелёный статус при повторном открытии окна означает, что токен сохранён локально; актуальность входа и прав подтверждается последующими запросами. Если сессия перестала работать, снова войдите в кабинет, выполните телефонную проверку при необходимости и повторите инициализацию.

## 2. Найти события и выгрузить аудит

1. Укажите **дату начала** и **дату окончания**.
2. Выберите типы событий. При открытии окна отмечены **«Удаление в корзину»** и **«Удаление навсегда»**. Есть также отправка, получение, пересылка, копирование, перемещение, просмотр, отметка непрочитанным, спам и ответ. Для всех типов используйте **«Выбрать все события»**.
3. Нажмите **«Найти события»**. После завершения появятся количество событий и количество уникальных MID.
4. Для отдельного файла нажмите **«Экспорт событий в XLSX»**.

Поиск выполняется для одного UID и выбранных типов событий. Одно письмо может соответствовать нескольким событиям, поэтому количество событий и уникальных MID различается. Перед каждым поиском проверяйте галочки: при повторном открытии окна два типа удаления снова отмечены по умолчанию.

Границы периода рассчитываются кодом через локальное время браузера; отдельного выбора часового пояса нет. В XLSX поле `date` записывается в ISO-формате UTC, а `date_timestamp` сохраняет исходное числовое значение. Для проверки событий у границ периода используйте эти поля.

Новый поиск аудит-лога очищает предыдущие локальные результаты поиска в архиве, список архивных писем и отчёт о пересылке. После изменения организации, UID, периода или типов событий заново выполните поиск аудита и последующие шаги.

## 3. Найти письма в архиве и проверить совпадения

1. После успешного поиска аудита нажмите **«Создать поиск в архиве»**. Расширение создаст поиск для сотрудника и дат, которые сейчас указаны в полях периода. Не меняйте их между поиском аудита и созданием поиска в архиве.
2. Дождитесь идентификатора поиска, затем нажмите **«Проверить количество писем для пересылки»**.
3. Сверьте результат: число совпадений по MID, число ожидаемых уникальных MID из аудита и общее число полученных записей архива за период.
4. При необходимости нажмите **«Экспорт всех писем из архива в XLSX»**. Эта выгрузка доступна после получения непустого списка архива и не требует пересылки.

Сначала обходится выдача архивного поиска, затем `mid` каждой записи точно сравнивается с MID из найденных событий. Пустые и нулевые MID в подбор для пересылки не включаются. Совпадения по теме, отправителю или времени вместо MID не используются. Предварительное число совпадений считает записи архива; дубликаты выдачи отдельно не устраняются, поэтому оно не обязательно равно количеству уникальных MID.

Экспорт архива содержит все полученные записи текущего архивного поиска, включая записи без совпадения с аудитом. Надпись кнопки «Экспорт всех писем» означает выгрузку их метаданных в таблицу, а не скачивание содержимого писем.

## 4. Переслать найденные письма

1. Проверьте результаты подсчёта и укажите адрес в поле **«Ящик для пересылки (куда)»**.
2. Явно нажмите **«Переслать найденные письма»**. Кнопка появляется после проверки, если есть совпадения. Создание поиска и предварительный подсчёт письма не пересылают.
3. Дождитесь сводки: сколько писем переслано, сколько уникальных MID ожидалось и сколько MID не найдено в архиве.
4. Нажмите **«Экспорт отчета пересылки в XLSX»**, чтобы сохранить результат по каждому письму, для которого выполнялась пересылка.

Перед пересылкой архив сканируется заново. В обработку попадают записи с MID из аудит-лога. Список может отличаться от предварительного подсчёта, если серверная выдача изменилась.

Статус `OK` в отчёте означает успешный ответ API на пересылку; фактическое получение проверяется в целевом ящике. `Failed` содержит последнюю ошибку после попыток. MID, которых не оказалось в архивной выдаче, не создают строки отчёта: они учитываются в показателе «Не найдено». Ошибка пересылки уже найденного письма и отсутствие MID в архиве — разные результаты.

Повторное нажатие запускает пересылку совпадений заново. Код не исключает письма, уже успешно пересланные предыдущим запуском. Если ответ на отправку потерялся из-за сетевого сбоя, автоматическая повторная попытка также может привести к повторной отправке.

## Какие файлы создаются

| Файл / лист | Содержание |
|---|---|
| `audit_log_<дата>_<UID>.xlsx` / `AuditLog` | События: UID и логин сотрудника, организация, тип и время события, тема, MID и другие идентификаторы, отправитель и получатели, папка, метки, IP клиента и другие явно выбранные кодом поля |
| `stash_messages_<дата>_<UID>.xlsx` / `StashMessages` | Метаданные полученных записей архива: UID, MID, Message-ID, тема, время, отправитель и адресаты, папка, метки и размер; часть общих с аудитом колонок остаётся пустой |
| `forward_report_<дата>.xlsx` / `ForwardReport` | MID, тема, целевой адрес, статус `OK`/`Failed` и текст ошибки |

Дата в имени файла — дата экспорта в UTC. Заголовки колонок и служебные значения сохраняются в формате исходного расширения.

## Обход страниц и повторы

| Операция | Поведение кода |
|---|---|
| Аудит | Запрашивает по 100 событий и следует курсору `next`; перед следующей страницей ждёт 500 мс. Отдельного цикла повторов при сетевой ошибке нет |
| Список архива | Запрашивает по 20 записей, следует `next`, между страницами ждёт 1 секунду. Для одной страницы допускает до 5 попыток при ошибке или пустом ответе без `next`. После неудачных попыток ждёт соответственно 1,5; 3; 4,5; 6 и 7,5 секунды |
| Пересылка | На письмо допускается до 3 попыток, включая первую, при ошибке API или сети; между попытками — 1 секунда. После обработки каждого письма — 500 мс |

Если API сообщает об ошибке служебного токена `ckey`, запрос дополнительно повторяется один раз с обновлённым токеном. Этот повтор действует и внутри перечисленных попыток.

После пяти неудачных попыток получить страницу архива код считает её концом выдачи и возвращает уже собранные записи. Поэтому показанное завершение сканирования само по себе не доказывает полноту списка при ошибках сервера. Общего ограничения числа страниц и защиты от повторяющегося `next` нет. Кнопка отмены и явный таймаут сетевых запросов не предусмотрены.

## Сохранение результатов и сброс

Поля формы, события аудита, идентификатор архивного поиска, полученные метаданные писем, отчёт и полученный служебный токен сохраняются в локальном хранилище расширения. Результаты восстанавливаются при открытии окна, если сохранение завершилось успешно. Если появилось сообщение об ошибке сохранения, сразу экспортируйте доступные данные, не закрывая окно.

Промежуточных контрольных точек для незавершённого поиска или пересылки нет. После закрытия окна или перезапуска браузера не рассчитывайте на продолжение с прерванного места. Перед пересылкой после повторного открытия окна снова выполните проверку количества.

Кнопка **«Сбросить сессию и результаты поиска»** запрашивает подтверждение и очищает локальные события, архивный поиск, список писем, отчёт и служебные токены. Кнопки проверки архива, пересылки и экспорта архива/отчёта скрываются. Для нового запуска начните с инициализации. Значения полей формы сохраняются. Сброс не выходит из аккаунта в кабинете, не удаляет созданный поиск на сервере и не отменяет уже выполненную пересылку.

Инструкция сверена с кодом версии 1.3. Проверены синтаксис JavaScript и наличие файлов, указанных в manifest и HTML. Полный сценарий с реальной авторизацией, телефонной проверкой и пересылкой при подготовке этой публикации не запускался.
