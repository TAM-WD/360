# Телемост — открыть в приложении

Расширение Chromium, Manifest V3, версия **1.2.0**. Перехватывает клики по ссылкам и навигацию верхнего уровня: ввод URL в адресной строке, выделение текста → правая кнопка → «Перейти по адресу», открытие ссылки через контекстное меню браузера. Поддерживаются оба домена по следующим правилам:

| Ссылка | Системная ассоциация |
| --- | --- |
| `https://telemost.yandex.ru/j/<идентификатор>` | `telemost://<полный HTTPS-URL>` |
| `https://telemost.360.yandex.ru/j/<идентификатор>` | `telemost://<полный HTTPS-URL>` |
| `https://telemost.yandex.ru/join#<непустой фрагмент>` | `telemost://ychat/telemost.yandex.ru/join#<непустой фрагмент>` |
| `https://telemost.360.yandex.ru/join#<непустой фрагмент>` | `telemost://ychat/telemost.360.yandex.ru/join#<непустой фрагмент>` |

Например, `https://telemost.360.yandex.ru/j/123?source=calendar#room` передаётся как `telemost://https://telemost.360.yandex.ru/j/123?source=calendar#room`, а `https://telemost.360.yandex.ru/join#room%2F123` — как `telemost://ychat/telemost.360.yandex.ru/join#room%2F123`. Для `/join#…` префикс `https://` удаляется, а исходный домен сохраняется. Параметры query и содержимое фрагмента передаются полностью, без дополнительного кодирования URL.

Другие ссылки открываются обычным способом, включая корень сайта, `/j/` без идентификатора, `/join` без непустого фрагмента и `/join/#…` с лишним слешем. Нестандартные порты и ссылки с логином/паролем не перехватываются.

При клике по подходящей HTML/SVG-ссылке переход отменяется обработчиком страницы: новая вкладка не создаётся, исходная страница остаётся открытой.

При переходе через адресную строку или меню браузера работает фоновый обработчик `webNavigation`:

- Если адрес введён в существующей вкладке с обычной страницей, расширение возвращает её к прежнему адресу и вызывает приложение. В отдельных случаях прежняя страница перезагружается: сохранение незаполненной формы не гарантируется.
- Если переход начался в пустой/новой вкладке и в том же окне есть другая загруженная вкладка, запрос на запуск приложения передаётся через неё, а лишняя вкладка закрывается автоматически. Диалог подтверждения остаётся в сохраняемой вкладке.
- Если подходящей другой вкладки нет или текущая вкладка закреплена, остаётся страница «Открытие Телемоста» с кнопкой закрытия. Автоматически закрывать единственную вкладку с ожидающим подтверждением нельзя: это может отменить запуск приложения.
- Если пользователь успел уйти со служебной страницы на другой сайт, расширение эту вкладку не закрывает.

`webNavigation` не отменяет запрос синхронно: вкладка может кратко появиться, а HTTPS-запрос — успеть начаться. Расширение не регистрирует протоколы в ОС; должен быть настроен обработчик `telemost://`.

## Установка

1. Распакуйте архив и сохраните папку `telemost-opener` в постоянном месте.
2. Откройте `chrome://extensions` (Edge: `edge://extensions`, Яндекс Браузер: `browser://extensions`).
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение** и выберите папку `telemost-opener`, в которой лежит `manifest.json`.
5. В настройках доступа расширения к сайтам разрешите работу **на всех сайтах**.
6. Обновите уже открытые страницы, чтобы подключился обработчик ссылок.
7. При первом переходе подтвердите открытие приложения для выбранного протокола в диалоге браузера. Если браузер предлагает запомнить разрешение, можно включить эту опцию.

Для локальных HTML-файлов отдельно включите **Разрешить доступ к URL файлов**, для инкогнито — соответствующее разрешение в настройках расширения.

## Поддерживается

- Обычный клик, Ctrl+клик (Windows/Linux), Cmd+клик (macOS), Shift+клик, средняя кнопка мыши. На macOS Ctrl+клик сохраняет стандартное контекстное меню.
- Открытие сфокусированной ссылки клавишей Enter через стандартное событие click браузера.
- Ссылки с `target="_blank"`, вложенными иконками, SVG и image map.
- Динамически добавленные ссылки, открытый Shadow DOM, обычные iframe и связанные `about:blank`/`srcdoc`-фреймы.
- Абсолютные и относительные ссылки: адрес разрешается относительно `baseURI` элемента. Путь, query и hash сохраняются; стандартный URL-парсер может нормализовать написание адреса.

Расширение не меняет `href`: копирование ссылки продолжает отдавать исходный HTTPS-адрес. Другие домены, включая похожие имена вида `telemost.yandex.ru.example.com`, не перехватываются.

## Границы работы

- Chromium запрещает внедрение расширений на служебные страницы (`chrome://`, страницы других расширений, защищённые страницы магазина расширений). Обработчик кликов там не работает; исходящий переход на подходящий HTTPS-адрес может обработать фоновый процесс.
- Фоновый обработчик работает с верхним документом вкладки. Самостоятельная навигация внутри iframe не перенаправляет всю вкладку в приложение.
- Кнопки с `window.open()` и программные переходы на подходящий HTTPS-адрес обрабатываются фоновым обработчиком, если Chromium сообщает навигацию верхнего уровня. Цепочки HTTP-редиректов через промежуточные сервисы не гарантируются.
- Закрытый Shadow DOM скрывает внутреннюю ссылку от обработчика. Строго изолированные sandbox-фреймы, политики браузера или сайта могут запрещать запуск внешнего протокола.
- Если соответствующее приложение не установлено, системная ассоциация отсутствует или пользователь отменил диалог, браузер не запустит приложение. Автоматического открытия веб-версии нет; событие перехода уже отменено.

Расширение работает локально, без внешнего сервера и аналитики. Разрешения: `webNavigation` — события переходов, `tabs` — адреса и закрытие вкладок, `storage` — временное состояние фонового обработчика. Доступ ко всем сайтам нужен для перехвата кликов. В `storage.session` сохраняются последний адрес каждой вкладки и незавершённая передача ссылки; записи удаляются при закрытии вкладки/завершении передачи и не сохраняются между запусками браузера. Доступ к cookies и API истории не используется.

## Проверка и обновление

Страница `test-page.html` содержит ссылки для ручной проверки. Откройте её как локальный файл после включения доступа к файлам или через локальный HTTP-сервер. Тестовые номера встреч вымышлены: страница проверяет вызов приложения, а не подключение к существующей встрече.

Для обновления с предыдущей версии замените файлы в уже подключённой папке расширения, нажмите **Обновить** на его карточке в `chrome://extensions` и перезагрузите открытые страницы. Подтвердите новые разрешения, если браузер запросит их. На карточке должна появиться версия **1.2.0**. Для отключения используйте переключатель на карточке.

Автоматические проверки без сторонних зависимостей: `node --test tests/content.test.cjs` (Node.js 18+). Они проверяют фильтрацию адресов, отмену перехода, обработку событий и строку протокола с подменённым системным вызовом. Запуск реального приложения и его диалог требуют ручной проверки на целевом ПК.

Браузерные проверки: установите Playwright (`npm install --no-save playwright`), скачайте его Chromium (`npx playwright install chromium --no-shell`), затем запустите `node tests/browser.cjs`. Необязательная переменная `CHROMIUM_PATH` задаёт путь к другому исполняемому файлу Chromium. Скрипт создаёт и удаляет отдельный временный профиль, загружает тестовую копию расширения и подменяет только последнюю строку вызова протокола; реальные приложения не запускаются. Личный профиль браузера не используется.

Проверки фоновой навигации: `node tests/navigation.cjs`. Скрипт проверяет закрытие новых вкладок, возврат существующей страницы, оба домена и оба маршрута, быстрый/медленный ответ сервера, изменение фрагмента, исключения, закреплённые вкладки, уход пользователя на другой сайт и ошибку запуска. Ввод адреса моделируется через CDP `Page.navigate` с типом `typed`, создание вкладки — через реальное `window.open()`. Сам пункт системного контекстного меню не автоматизируется; проверяется создаваемая им навигация. Конечный вызов ОС подменён записью аргументов, остальные API расширения работают в настоящем браузере.

Контрольный запуск `BASELINE=1 node tests/navigation.cjs` отключает в тестовой копии только закрытие вкладки: тест подтверждает, что после передачи ссылки она остаётся открытой. Обычный запуск проверяет её автоматическое закрытие.

Версия 1.2.0: прошли **70** проверок логики кликов, **30** браузерных сценариев кликов и **26** проверок фоновой навигации в Chrome for Testing **151.0.7922.34**, macOS. Личные профили браузера не использовались. Точные строки протокола проверены до передачи браузеру/ОС; дальнейшая нормализация URI зависит от платформы. Запуск самого Телемоста и его обработку номера встречи нужно проверить на целевом ПК.

Дополнительный системный тест на macOS: `node tests/native-macos.cjs` (Playwright, Chromium и системные `osacompile`/`codesign`). Он создаёт временное приложение в текущей рабочей папке, регистрирует уникальную тестовую схему и разрешает её только в отдельном тестовом профиле Chromium. После проверки регистрация и файлы удаляются. Сама ассоциация `telemost://` не меняется. В проверке версии 1.2.0 приложение получило все **4** варианта ссылки, новые вкладки закрылись, исходная страница осталась открыта. Проверка подтверждает системную передачу URL тестовому обработчику; запуск самого Телемоста и интерактивный диалог подтверждения в неё не входят.
