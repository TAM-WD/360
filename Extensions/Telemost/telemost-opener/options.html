Ссылки открываются там, где удобно

Выберите типы ссылок и добавьте правила для своих приложений. Настройки действуют и для кликов, и для переходов через адресную строку.

Правила открытия

Своё приложение

Вставьте пример обычной ссылки и соответствующий ей адрес приложения. Расширение предложит подстановку; проверьте её на другом адресе.

При сохранении значения переменных в примерах заменяются тестовыми: числа — на 123456, текст и коды — на a1b2c3. Домены и постоянные части шаблона сохраняются. Точное правило без переменных сначала нужно обобщить.



Изменить шаблон вручную

JSON содержит условия, подстановку и исходную пару. Изменяйте его, если одной пары недостаточно для определения правила.



В условии пути можно выделить часть сегмента: "pathname": "/+{invite}". В адрес приложения подставьте {capture:invite} — код без фиксированного +. Имя выбираете вы. Допускается одна переменная на сегмент, в том числе с префиксом и суффиксом: /file-{id}.json.


Для ссылок вида #/staff/имя задайте условие match.hashPathname. Переменные: {hashPathAndQuery} — весь путь после # с параметрами, {hashPathname} — без параметров, {hashPath:1} — второй сегмент, {hashTail} — остаток условия с {tail}.




Справочник переменных с примерами

Пример исходной ссылки:
https://example.org:8443/room/123/details?id=456&mode=guest#chat




ПеременнаяЧто подставляетРезультат для примера



{host}Домен с портом, если он есть; без схемы и пути.example.org:8443


{pathname}Весь путь с начальным /, без query и фрагмента./room/123/details


{pathAndQuery}Путь вместе с query и фрагментом, включая ? и #./room/123/details?id=456&mode=guest#chat


{search}Все параметры после ?, включая сам ?. Без параметров — пустая строка.?id=456&mode=guest


{hash}Фрагмент вместе с #. Без фрагмента — пустая строка.#chat


{fragment}Фрагмент без #.chat


{tail}Остаток пути для условия /room/{tail}, без query и фрагмента.123/details


{path:1}Второй целый сегмент пути. Нумерация начинается с 0.123


{query:id}Значение параметра id из query, без имени параметра.456




{capture:invite} берёт значение переменной {invite} из условия пути. Для /+{invite} и ссылки https://t.me/+ABC результат — ABC; {path:0} при этом даёт целый сегмент +ABC. Для именованных переменных внутри hashPathname используется {hashCapture:имя}.


Имя переменной: 1–40 латинских букв, цифр или _, начиная с буквы; регистр учитывается. Имя должно однозначно определять одну переменную в своём пути. {tail} — специальное обозначение всего непустого остатка пути; оно занимает последний сегмент целиком.


URL-кодирование сохраняется: %2F не превращается в /. Для дополнительного кодирования добавьте |encode, например {capture:invite|encode}. Если query-параметр отсутствует или повторён, его подстановка не выполняется; queryKeys: ["id"] также требует непустого значения. {url} передаёт весь URL, {urlNoScheme} — URL без схемы.







Файлы настроек и правил
config.json содержит настройки, rules.json — правила поставки. Пользовательские правила автоматически сохраняются отдельно в user-rules.json внутри профиля браузера. Чтобы получить обычный файл для переноса или резервной копии, скачайте его ниже.


При импорте настроек меняются только разрешённые переключатели. Импорт user-rules.json заменяет личные правила и сохраняет тестовые примеры. Правила поставки заменяются в файле rules.json папки расширения. Старый общий JSON тоже можно импортировать.
