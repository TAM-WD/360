# Инструкция по запуску скрипта автоконспектирования Яндекс Телемоста

## 1. Что делает скрипт

Скрипт находит созданные в организации встречи Яндекс Телемоста по событиям
аудит-лога и включает для них автоматическое конспектирование. Изменение встречи
выполняется от лица её организатора с помощью временного токена сервисного
приложения.

Поддерживаются три основных сценария:

| Сценарий | `DRY_RUN` | `MANUAL_TASKS` | Что произойдёт |
|---|---:|---|---|
| Тест по аудит-логу | `True` | `[]` | Встречи будут найдены и показаны, но не изменены |
| Обычный разовый запуск | `False` | `[]` | Будут обработаны новые встречи из аудит-лога |
| Регулярный запуск | `False` | `[]` | То же самое, но по расписанию `cron` |

Есть также ручной режим для одной или нескольких известных встреч:

```python
MANUAL_TASKS = [
    ('ID_ВСТРЕЧИ', 'UID_ОРГАНИЗАТОРА'),
]
```

В ручном режиме аудит-лог не читается.

> Важно: у скрипта нет аргументов командной строки. Режим работы задаётся
> константами непосредственно в файле скрипта.

## 2. Требования и доступы

Потребуются:

- Python 3.7 или новее;
- пакет `requests`;
- исходящий HTTPS-доступ к `cloud-api.yandex.net` и `oauth.yandex.ru`;
- OAuth-приложение с правом `ya360_security:read_auditlog`;
- сервисное приложение с правом `telemost-api:conferences.update`;
- ID организации, OAuth-токен, `client_id` и `client_secret` сервисного приложения.

Пользователь, от имени которого запускается скрипт, должен иметь право записи в
каталог со скриптом: там создаются логи, отчёты и файл состояния.

## 3. Первичная установка

Сохраните скрипт под понятным именем с расширением `.py`, например:

```text
/absolute/path/telemost-autosummary/telemost_autosummary.py
```

Создайте виртуальное окружение и установите зависимость:

```bash
cd /absolute/path/telemost-autosummary
python3 -m venv .venv
./.venv/bin/python -m pip install requests
```

Проверьте, что файл запускается выбранным интерпретатором:

```bash
./.venv/bin/python telemost_autosummary.py
```

До заполнения реквизитов скрипт штатно завершится сообщением о недостающих
параметрах.

## 4. Настройка реквизитов

Не рекомендуется сохранять токены и секреты непосредственно в исходном коде.
Скрипт поддерживает переменные окружения, которые имеют приоритет над значениями
в секции конфигурации.

Создайте рядом со скриптом файл `telemost.env`:

```bash
export YA360_ORG_ID='ID_ОРГАНИЗАЦИИ'
export YA360_AUDIT_TOKEN='OAUTH_ТОКЕН_ДЛЯ_АУДИТ_ЛОГА'
export YA360_CLIENT_ID='CLIENT_ID_СЕРВИСНОГО_ПРИЛОЖЕНИЯ'
export YA360_CLIENT_SECRET='CLIENT_SECRET_СЕРВИСНОГО_ПРИЛОЖЕНИЯ'
```

Ограничьте доступ к файлу:

```bash
chmod 600 telemost.env
```

Перед ручным запуском загрузите переменные в текущую оболочку:

```bash
cd /absolute/path/telemost-autosummary
. ./telemost.env
./.venv/bin/python ./telemost_autosummary.py
```

Скрипт в текущей реализации проверяет наличие всех четырёх параметров даже при
обычном тестовом запуске, поэтому заполните их заранее.

## 5. Безопасный тестовый запуск

Для теста по аудит-логу установите в скрипте:

```python
DRY_RUN = True
MANUAL_TASKS = []
ENABLE_AUTO_SUMMARIZATION = True
```

Оставьте `DATE_FROM` и `DATE_TO` пустыми. Для короткой проверки можно оставить:

```python
LOOKBACK_MINUTES = 15
OVERLAP_MINUTES = 120
```

Запустите:

```bash
cd /absolute/path/telemost-autosummary
. ./telemost.env
./.venv/bin/python ./telemost_autosummary.py
```

В начале вывода должны появиться строки `РЕЖИМ ТЕСТА` и `ничего не меняем`, а у
найденных встреч — сообщение `[ТЕСТ]`. В этом режиме скрипт:

- читает аудит-лог;
- применяет период и фильтры;
- формирует лог и CSV-отчёт;
- не получает временные токены организаторов;
- не отправляет `PATCH` и не меняет встречи.

Если нужно проверить одну конкретную встречу без чтения аудит-лога, задайте:

```python
DRY_RUN = True
MANUAL_TASKS = [
    ('1234567890', '11300000123456789'),
]
```

Замените значения на реальные ID встречи и UID её организатора. Такой сухой
запуск не проверяет выдачу временного токена и право на изменение встречи — он
только показывает планируемое действие.

## 6. Обычный разовый запуск

После успешного теста измените настройки:

```python
DRY_RUN = False
MANUAL_TASKS = []
ENABLE_AUTO_SUMMARIZATION = True
```

Запустите той же командой:

```bash
cd /absolute/path/telemost-autosummary
. ./telemost.env
./.venv/bin/python ./telemost_autosummary.py
```

При успешной обработке в логе появится сообщение `Готово: автоконспектирование
включено`. Сначала рекомендуется провести реальный запуск на тестовой встрече и
проверить результат в интерфейсе Телемоста.

Чтобы вместо включения отключать автоконспектирование, задайте:

```python
ENABLE_AUTO_SUMMARIZATION = False
```

Учтите файл состояния: уже обработанные встречи не будут автоматически
обработаны повторно только из-за смены значения с `True` на `False`.

## 7. Регулярный запуск через cron

Для регулярной работы должны быть установлены:

```python
DRY_RUN = False
MANUAL_TASKS = []
DATE_FROM = ''
DATE_TO = ''
```

Период в `cron` должен соответствовать `LOOKBACK_MINUTES`:

- каждые 15 минут — `LOOKBACK_MINUTES = 15`;
- каждый час — `LOOKBACK_MINUTES = 60`;
- раз в сутки — `LOOKBACK_MINUTES = 1440`.

Создайте рядом со скриптом файл `run_telemost.sh`:

```sh
#!/bin/sh
set -eu

APP_DIR='/absolute/path/telemost-autosummary'
. "$APP_DIR/telemost.env"

exec "$APP_DIR/.venv/bin/python" "$APP_DIR/telemost_autosummary.py"
```

Подставьте реальный абсолютный путь и разрешите запуск файла:

```bash
chmod 700 /absolute/path/telemost-autosummary/run_telemost.sh
```

Сначала выполните обёртку вручную:

```bash
/absolute/path/telemost-autosummary/run_telemost.sh
```

Затем откройте расписание:

```bash
crontab -e
```

Добавьте **одну** из строк ниже.

Каждые 15 минут:

```cron
*/15 * * * * /absolute/path/telemost-autosummary/run_telemost.sh >> /absolute/path/telemost-autosummary/scheduler.log 2>&1
```

Каждый час:

```cron
0 * * * * /absolute/path/telemost-autosummary/run_telemost.sh >> /absolute/path/telemost-autosummary/scheduler.log 2>&1
```

Раз в сутки в 03:00:

```cron
0 3 * * * /absolute/path/telemost-autosummary/run_telemost.sh >> /absolute/path/telemost-autosummary/scheduler.log 2>&1
```

Проверьте сохранённое расписание:

```bash
crontab -l
```

В `cron` обязательно используйте абсолютные пути: планировщик обычно не читает
профиль интерактивной оболочки и запускается с сокращённым окружением.

Не допускайте одновременного запуска двух экземпляров. В самом скрипте нет
блокировки файла состояния. Если один запуск может длиться дольше интервала,
увеличьте интервал или добавьте внешнюю блокировку средствами вашей ОС.

## 8. Где искать результаты

Скрипт создаёт:

```text
telemost_autosummary_out/logs/<имя_скрипта>_<дата_время>.log
telemost_autosummary_out/reports/<имя_скрипта>_<дата_время>.csv
telemost_autosummary_state.json
```

Пути отсчитываются от каталога, в котором находится файл `.py`.

Логи и CSV могут содержать ID встреч, имена, email и UID организаторов. Доступ к
каталогу с результатами следует ограничить.

Файл `telemost_autosummary_state.json` защищает от повторной обработки одной и
той же встречи. Записи со статусом `ok` или `permanent_error` пропускаются в
течение 14 дней. Не удаляйте файл состояния во время штатной работы. Перед его
ручным изменением сделайте резервную копию и остановите регулярный запуск.

Режим `DRY_RUN` не добавляет новые встречи в состояние, но учитывает записи,
оставшиеся от предыдущих реальных запусков.

## 9. Коды завершения и типовые проблемы

- `0` — запуск завершён успешно, в том числе когда новых встреч нет;
- `1` — были ошибки обработки или критическая ошибка;
- `2` — не заполнена конфигурация или неверно задан период;
- `130` — запуск прерван через `Ctrl+C`.

Если встречи не найдены, проверьте:

- создавались ли встречи в выбранном периоде;
- правильны ли `ORGID` и `AUDIT_TOKEN`;
- есть ли у OAuth-приложения право `ya360_security:read_auditlog`;
- не обработаны ли эти встречи ранее согласно файлу состояния;
- успели ли события появиться в аудит-логе; за задержку отвечает запас
  `OVERLAP_MINUTES`.

Если временный токен не выдаётся или Телемост отвечает `403`, проверьте
`CLIENT_ID`, `CLIENT_SECRET` и право сервисного приложения
`telemost-api:conferences.update`.

Встречи внешних организаторов, для которых нельзя выпустить доменный временный
токен, скрипт пропускает.
